# راهنمای کاربری MCP Gateway

## ۱. پیش‌نیاز

- Docker و Docker Compose

## ۲. اجرا

```bash
cd mcp-gateway
docker compose up --build
```

| سرویس | آدرس |
| --- | --- |
| پنل (فارسی/RTL) | http://localhost:3001 |
| Gateway API / MCP | http://localhost:8000 |
| demo-mcp | http://localhost:8100/mcp |
| health | http://localhost:8000/health |

درخواست‌های UI از مسیر `/gw/*` به backend پروکسی می‌شوند (بدون CORS مرورگر). پاسخ‌های `204` (مثل حذف سرور) هم درست از proxy عبور می‌کنند.

## ۳. ورود

بدون login داشبورد باز نمی‌شود.

| نقش | نام کاربری | رمز |
| --- | --- | --- |
| ادمین پیش‌فرض | `admin` | `dev-admin-key` |
| کاربر عادی | همان که ادمین ساخته | همان رمزی که ادمین گذاشته |

پس از ورود، session token در `sessionStorage` ذخیره می‌شود و با header مربوط به `Authorization: Bearer ...` ارسال می‌گردد.

## ۴. فلو صحیح دمو

### مرحله A — کار ادمین (کاتالوگ MCP)

1. با `admin` وارد شوید  
2. بروید به **کاتالوگ MCP**  
3. یا `افزودن / باز کردن demo-mcp` را بزنید، یا با **نام یکتا** و Base URL یک MCP جدید اضافه کنید  
4. اگر MCP عمومی/hosted هدر می‌خواهد (مثلاً API key)، فیلد **هدر احراز upstream** را با مقدار کامل `Authorization` پر کنید؛ مثل `Bearer sk-...`  
5. برای هر سرور **Sync** کنید تا toolها بیایند  
6. در صورت نیاز با دکمه حذف (سطل زباله / حذف سرور) MCP را از کاتالوگ بردارید  
7. بروید به **کاربران** و یک کاربر با username/password بسازید  

> نکته: دکمه demo-mcp فقط یک نمونه آماده است. برای MCPهای بیشتر همیشه نام جدید بدهید (نام تکراری قبول نمی‌شود). آدرس می‌تواند یکسان باشد.  
> نکتهٔ هدر: این هدر فقط برای ارتباط Gateway با upstream است و به کلاینت AI داده نمی‌شود. اتصال کلاینت به Gateway همان `Authorization: Bearer mcpgw_...` می‌ماند؛ نیازی به چند پروتکل یا کاستوم‌هدر پیچیده روی کلاینت نیست.

### مرحله B — کار کاربر (ساخت و ویرایش Gateway)

1. خروج کنید  
2. با username/password همان کاربر وارد شوید  
3. بروید به **Gateway من**  
4. از لیست MCP/toolها موارد لازم را روشن کنید (مثلاً فقط `notes_list`)  
5. **ساخت Gateway** را بزنید و platform token را کپی کنید  
6. برای تغییر بعدی: روی همان token **ویرایش toolها** بزنید، سوییچ‌ها را کم/زیاد کنید، **ذخیره تغییرات**  
7. خودِ token عوض نمی‌شود؛ فقط allowlist به‌روز می‌شود  
8. در صفحهٔ **اتصال** URL و snippet را بردارید  

### مرحله C — کلاینت AI

```json
{
  "mcpServers": {
    "mcp-gateway": {
      "url": "http://localhost:8000/mcp",
      "headers": {
        "Authorization": "Bearer mcpgw_XXXXXXXX"
      }
    }
  }
}
```

بعد از ویرایش toolها، کلاینت با همان token در `tools/list` بعدی مجموعهٔ جدید را می‌بیند.

## ۵. نقشهٔ صفحات

| صفحه | مسیر | چه کسی | کار |
| --- | --- | --- | --- |
| ورود | `/login` | همه | authentication |
| نمای کلی | `/` | همه | خلاصه وضعیت |
| Gateway من | `/gateway` | کاربر/ادمین | ساخت token + ویرایش allowlist |
| کاربران | `/users` | فقط ادمین | ساخت کاربر با رمز |
| کاتالوگ MCP | `/servers` | ادمین مدیریت؛ کاربر مشاهده | افزودن/Sync/حذف سرور |
| اتصال | `/connect` | همه | راهنمای وصل شدن کلاینت |

## ۶. وضعیت سرور

| وضعیت | معنی |
| --- | --- |
| registered | ثبت شده |
| online | آخرین Sync موفق |
| error | Sync خطا داشته |

## ۷. خطاهای متداول

| مشکل | کار |
| --- | --- |
| CORS / login خراب | UI را از پورت compose باز کنید (`3001`) و از `/login` وارد شوید |
| کاتالوگ tool خالی است | ادمین باید Sync کند |
| Sync خطا می‌دهد | وضعیت کانتینر `demo-mcp` را چک کنید |
| «نام تکراری» هنگام افزودن MCP | نام یکتای دیگری بگذارید |
| حذف MCP خطا می‌دهد | صفحه را رفرش کنید؛ نسخهٔ فعلی proxy پاسخ `204` را درست برمی‌گرداند |
| کاربر صفحه کاربران را نمی‌بیند | طبیعی است؛ فقط ادمین می‌بیند |
| ویرایش Gateway کار نمی‌کند | token نباید باطل شده باشد؛ حداقل یک tool بماند |

## ۸. توقف

```bash
docker compose down
```

دادهٔ SQLite در volume مربوط به `gateway-data` می‌ماند مگر volume را پاک کنید.
