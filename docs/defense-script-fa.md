# اسکریپت ارائهٔ دفاع (۶ تا ۸ دقیقه)

## ۰. آماده‌سازی
- `docker compose up --build` از قبل بالا باشد
- UI روی `localhost:3001`
- در صورت نیاز اسکریپت `./scripts/eval_scenarios.sh` آماده باشد

## ۱. عنوان (۲۰ ثانیه)
یک MCP Gateway مینیمال ساختم که کاربر با حساب خودش وارد می‌شود، از لیست MCP/tool انتخاب می‌کند، platform token می‌گیرد، و کلاینت فقط همان toolها را می‌بیند.

## ۲. مسئله (۶۰ ثانیه)
MCP اتصال به tool را استاندارد می‌کند، اما پیکربندی پراکنده است و access control سطح tool معمولاً نیست. سؤال: چطور چند MCP را پشت یک endpoint با توکن و allowlist جمع کنیم؟

## ۳. راه‌حل (۷۰ ثانیه)
- ادمین کاتالوگ را مدیریت می‌کند (چند MCP، Sync، حذف)  
- کاربر با username/password وارد می‌شود  
- در «Gateway من» tool انتخاب می‌کند و بعداً می‌تواند ویرایش کند  
- platform token صادر می‌شود  
- `/mcp` فقط grantها را نشان می‌دهد  

## ۴. دمو (۳ دقیقه)
1. ورود ادمین → Sync مربوط به demo-mcp  
2. ساخت کاربر با رمز  
3. ورود با همان کاربر  
4. Gateway من → فقط `notes_list`  
5. نشان دادن list فقط همان tool؛ call مربوط به `tasks_add` رد می‌شود  
6. (اختیاری) ویرایش toolها → اضافه کردن `tasks_add` → list/call جدید  

## ۵. ارزیابی و محدودیت (۶۰ ثانیه)
اسکریپت سه سناریو را Pass می‌کند. OAuth سازمانی و K8s عمداً خارج از محدوده‌اند.

## ۶. جمع‌بندی (۲۰ ثانیه)
خروجی یک اپ usable است: login کاربر، ساخت و ویرایش Gateway، token، و سیاست واقعی روی MCP.
